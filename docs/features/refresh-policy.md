# 页面刷新时机

两端共用 `src/refreshPolicy.ts` 与 `App.tsx` 的自动刷新入口。

- 启动先显示本机缓存；当前账号的整轮数据超过十五分钟或未同步时，后台启动同步。
- 切换账号按新账号检查缓存时效，账号间互不借用数据。
- 进入业务页面、从后台回到前台、窗口重新获得焦点，以及可见页面停留期间按一分钟检查数据时效。
- 实际刷新受模块时效限制；手动按钮、下拉刷新不受时效限制。
- 正在同步时不再发起重复请求；离线、编辑文本、详情页和对话框打开时暂缓自动刷新。
- 自动刷新失败保留缓存，间隔五分钟再尝试；需要验证码时给出提示，手动登录后可恢复。
- 自动刷新成功不反复弹出成功提示，顶栏同步状态与更新时间反映过程；失败仍显示原因。

| 范围 | 缓存有效时间 |
| --- | --- |
| 首页整轮 | 15 分钟 |
| 邮箱 | 1 分钟 |
| 作业 | 5 分钟 |
| 成绩 | 10 分钟 |
| 课表 | 6 小时 |
| 资料目录 | 15 分钟 |
| 校园服务 | 5 分钟 |

文件空间、回放、教室、已发送和设备页面继续使用各自的加载与显式刷新，不将本地下载历史误作网络同步。新邮件与成绩后台检查间隔仍由通知设置控制，不依赖当前打开的页面。

退出或系统冻结应用后，不保证自动刷新和本地提醒执行。CLI 每条查询直接访问接口，独立于上述 GUI 页面缓存时效。
