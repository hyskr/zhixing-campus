# 系统通知与课程提醒

设置 → 通知与提醒，分别开启新邮件、新成绩和上课提醒。三项默认关闭，应用运行期间生效，退出后停止检查。

| 类型 | 检查方式 | 通知内容 |
| --- | --- | --- |
| 新邮件 | 按设置的 1–60 分钟检查当前账号收件箱 | 新增未读邮件数量与主题 |
| 新成绩 | 按独立设置的间隔读取教务成绩；手动同步成绩也参与比较 | 新增课程成绩或分数变化 |
| 上课 | 每 30 秒检查已同步课表，按教学周与单双周匹配 | 课程、北京时间、地点、教师 |

上课默认到点提醒，可选提前 5、10、15 或 30 分钟。选课任务课表不参与提醒。启动应用时仅处理提醒时刻后 90 秒内的课程，不补发当天较早的课程。

## 基线和重复通知

首次获取邮件或成绩只记录现有数据。之后比较新增邮件 ID 和成绩记录 ID／分数，不提醒全部历史。成绩基线、课程周次锚点及当天已提醒课程保存在应用数据目录 `reminders.json`；邮件基线保存在 `mail-baselines.json`。重启应用不会重复提醒同一课次。

已有前端缓存通过 `ReminderBridge` 恢复至提醒模块；课程周次基于教学周本身的同步时间计算，单独刷新邮箱、成绩不会重设课表的周次锚点。没有同步日期时，先同步课表。学校接口不可用或登录过期时保持上次缓存；重新登录并同步后继续检查。

## 测试通知

通知设置页提供邮件、成绩、上课三种测试按钮。按钮通过 `test_notification` 调用与业务提醒相同的 Tauri 原生投递路径。测试不发送邮件、不修改成绩和课表。

也可以从实际应用程序执行：

```bash
"知行 Campus.app/Contents/MacOS/zhixing-campus" --test-notification mail
```

将 `mail` 换为 `grade` 或 `course` 测试其他内容。终端 `submitted to system` 表示通知接口返回成功；是否展示横幅应在系统通知中心核对。Tauri 桌面插件的权限检查固定返回 Granted，不能用它证明系统横幅已出现。专注模式或系统通知设置可以隐藏横幅。

## 验证

- Rust 测试覆盖首次成绩基线、重复同步、分数更新、新课程成绩。
- 课表测试覆盖提前提醒、到点窗口、日期、单双周及序列化后去重。

## 实现与参考

新邮件协议和基线沿用 `campus.rs` 的收件箱实现，来源见 [来源对照](../references/sources.md)。成绩和课程调度由 `reminders.rs` 实现，通知使用项目现有 `tauri-plugin-notification`。设置控件复用 BeUI Switch、Select 和 Button。

## 2026-10-22 原生验证

在打包的 0.11.0 macOS 应用中调用三类测试通知，原生投递接口均返回成功。系统设置中原先关闭了知行通知，已按本次提醒需求开启，并在应用中启用当前账号的成绩与上课提醒；原有新邮件提醒保持开启。

系统同时设置为“镜像或共享屏幕时关闭通知”，测试环境正在共享窗口，因此没有确认可见横幅。此项系统全局策略保持原设置。测试结果证明应用发起了原生投递，不将返回成功等同于横幅已显示。

应用驻留托盘时，命令行测试参数由单实例回调转交给正在运行的实例。
